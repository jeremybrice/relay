Relay · learning layer · design walkthrough

Portable Learning + Memory

Relay is a session handoff plus lightweight self-learning tool, so agents get smarter in every repo it lives in. Active, deterministic, daemon-free, local-only, and the same across five CLIs.

Handoff spec README

S-01

One tool, two tiers

The daily handoff carries recent context. A second, durable tier holds knowledge that outlives the rolling 10-day window, with no cron, batch analyzer, or daemon. The deterministic helper does every file operation; the agent only authors prose.

Core: deterministic helper (relay.sh) Ephemeral: daily handoffs Durable: learned knowledge Graduated: standing instructions

Tier 1 Ephemeral handoffs

A 6-section handoff per session, a dated history file per day, and an index table with one row per day. Pruned at 10 days. Answers "what happened recently?"

Tier 2 Durable knowledge

Facts and lessons that never age out of the window. Captured at the same save moment, loaded every session. Lessons reinforce on recurrence and can graduate into AGENTS.md. Answers "what is permanently true here, and what have I learned about working here?"

Not ported from Forge: the SessionObserver cron, the /analyze-learning batch pipeline, confidence-score math, and time decay. Those depend on a daemon a dogfood repo won't have. Relay keeps the idea (capture, reinforce, graduate) and drops the machinery.

S-03

Data structure, files to folders

Everything lives under .session-log/, so the gitignore footprint is one line. The tool (.relay/) is committed and travels via git; the data is local-only.

repo-root/ ├─ .relay/committed │ ├─ relay.sh # the deterministic core │ ├─ adapters/ # templates the installer wires from │ └─ tests/smoke-compact.sh # compact / restore contract test │ ├─ .session-log/gitignored · local │ │ ── tier 1 · ephemeral ──────────────────────── │ ├─ latest.md # newest single-session handoff │ ├─ index.md # table, one row per day, ≤ 10 days │ ├─ relay-instructions.md # OpenCode only: load snapshot │ ├─ history/ │ │ ├─ 2026-10-16.md # one file per day · same-day appended │ │ └─ … # 10 most recent · older pruned │ │ │ │ ── tier 2 · durable, never pruned ──────────── │ └─ knowledge/ │ ├─ index.md # derived table cache · never read by load │ ├─ facts/ │ │ ├─ deploy-release-script.md │ │ ├─ deploy-release-script.conflict # pending divergent body │ │ ├─ superseded/ # tombstones: retired, lost conflicts │ │ └─ cold/ # archived by compact · restorable │ └─ lessons/ │ ├─ schema-types-first.md │ ├─ graduated/ # moved here on graduation │ ├─ superseded/ │ └─ cold/ │ ├─ .gitignore # + .session-log/ └─ AGENTS.md # one block per CLI + graduated regioncommitted <!-- relay:learned --> <!-- relay:learned:schema-types-first --> … <!-- /relay:learned:schema-types-first --> <!-- /relay:learned -->

Each entry is its own small file keyed by id (slugified, ≤ 48 chars); the atomic single-file rewrite is what makes counter bumps safe. knowledge/index.md is a derived convenience cache: rebuilt as padded tables after every knowledge write, never hand-edited, and never load-bearing. Load reads the entry files directly.

facts/<id>.md a durable truth

--- id: deploy-release-script kind: fact confirmed: 3 # reinforcement proxy first_seen: 2026-09-02 last_confirmed: 2026-10-16 ttl: none # days; none → 90-day default source: history/2026-09-02.md#session-2 status: active --- Deploys ship via scripts/release.sh, never `npm publish` directly.

Never graduates. A fact isn't an instruction. confirmed, ttl, and the helper-stamped source give it dedup, freshness, and an audit trail with no math.

lessons/<id>.md a behavioral pattern

--- id: schema-types-first kind: lesson seen: 4 sessions: 3 # DISTINCT dates first_seen: 2026-10-01 last_seen: 2026-10-16 source: history/2026-10-01.md#session-1 status: active graduated_to: null --- When editing the DB schema, regenerate types before touching call sites…

Graduates at sessions ≥ 3 (distinct dates, not raw seen). Re-asserting a lesson replaces its body with the newest wording. graduated_to lets list catch drift if the rule is later deleted.

S-05

One reflection, three destinations

Capture piggybacks on the save you already run. At wrap-up the agent reflects once and routes that reflection into three buckets; the helper does the writing.

Wrap-up cue → session-save
/session-save · $session-save · the session-save skill. Authoring happens before the lock.
sorts into
L-1 What happened today
The 6-section handoff: Summary, Changed, Decisions, Next, Watch out, Open questions. Piped on stdin with a one-line digest.
relay save --digest "…"
L-2 What's permanently true
A durable fact. Run --near first to reuse an existing id, then write with an explicit --id. A divergent body raises a conflict.
relay knowledge add --fact --near "…"
relay knowledge add --fact --id deploy-release-script "…"
L-3 What I learned here
A behavioral lesson with a stable id. The helper creates it or bumps seen, and sessions on a new day.
relay knowledge add --lesson --id schema-types-first "…"

Division of labor. The agent owns judgment: is this durable, does it match an existing entry, what is the id? The helper owns mechanics: append, bump, dedup, lock. A mid-session "remember this" runs the same knowledge add through relay-learn. When a lesson crosses the threshold, the helper prints graduation-ready and the agent offers it in one line.
S-06

relay load builds one block and prints it as plain text (Claude Code), Codex hookSpecificOutput.additionalContext JSON (--format codex), or top-level systemMessage JSON (--format grok). Graduation relocates; it doesn't shrink total context. A graduated lesson moves out of slot 04 and into AGENTS.md, which the CLI loads natively. That keeps Relay's block small and avoids double injection, but the instruction file is uncapped, so slot 05 nudges when it grows and ungraduate drains it.

Load never blocks: with no latest.md it prints nothing, and the hook wrappers swallow errors. Cursor has no hook, so its agent reads latest.md and index.md itself and does not see slots 03 to 05.

No confidence math, no cron. A counter, a threshold, and a gated append.

gated Why you approve graduation

Writing into AGENTS.md is a persistent, behavior-changing edit to a file you may commit, so the agent proposes and you okay it. There is no auto-graduate switch. The helper also prints a note naming the file it wrote.

retire Supersede by judgment

No time decay. A wrong entry is retired with supersede <id> (tombstoned in superseded/). A stale rule is drained with ungraduate <id>, which removes its block idempotently. Nothing is silently orphaned.

compact Keep the store small

knowledge compact dry-runs by default; --yes applies. Empty bodies go to superseded/; cold lessons and anything over the caps (40 facts, 30 lessons, weakest and oldest first) go to cold/. restore <id> brings one back.

The relay-compact skill wraps the mechanical pass with a human-gated semantic pass: merge duplicates, rewrite stale bodies after checking the repo, propose graduations and supersedes.

S-08

Adapters across five CLIs

Every adapter calls the same relay.sh; only the load surface and command location differ. Each appends one labeled block to AGENTS.md between # >>> relay >>> markers with the wrap-up (L2) instruction: save on "done for today", offer when unsure, capture knowledge, surface graduation-ready lessons.

Why changes land in the core, not the adapters. One edit inside cmd_load reaches every CLI and keeps them from drifting. Claude Code, Cursor, and Grok share one skill set (adapters/skills/); Codex and OpenCode carry their own copies because their command formats differ.
S-09

Command surface, all deterministic

Every write is a helper subcommand. The agent never edits knowledge files directly, which is what keeps counters trustworthy and graduation idempotent. Every command accepts --dir .session-log.

# ── handoff ── relay save --digest "…" < six-sections.md # append · latest · index · prune relay load [--format text|codex|grok] # the session-start block # ── capture ── relay knowledge add --fact --near "…" # 3 closest ids, writes nothing relay knowledge add --fact --id deploy-release-script [--ttl 30] "…" # new → confirmed:1 · similar → confirm · divergent → .conflict relay knowledge add --lesson --id schema-types-first "…" # new → seen:1 · again → seen+1, sessions+1 on a new day # ── resolve · retire ── relay knowledge resolve <id> [--keep new|existing] # default existing; loser tombstoned relay knowledge supersede <id> # tombstone an active entry relay knowledge prune [--yes] # list facts past freshness; --yes retires relay knowledge compact [--yes] # empties · cold lessons · caps relay knowledge restore <id> # bring a cold entry back # ── graduate (gated) · drain ── relay knowledge graduate schema-types-first # id-keyed block into AGENTS.md relay knowledge ungraduate schema-types-first # remove block · tombstone # ── inspect ── relay knowledge list # state · conflicts · graduated drift · cold counts relay knowledge why <id> # entry + the history it came from relay knowledge export # active facts + lessons to stdout

Tunables are environment variables: RELAY_GRADUATE_AT, RELAY_FACTS_CAP, RELAY_LESSONS_CAP, RELAY_FACT_STALE_DAYS, RELAY_LESSON_COLD_DAYS, RELAY_FACTS_MAX, RELAY_LESSONS_MAX, RELAY_GRADUATED_SOFT, and RELAY_INSTRUCTION_FILE to pin the graduation target.

S-11

Boundary and non-goals

What keeps this light and active instead of a second Forge.

in scope Shipped

  • Durable facts and behavioral lessons, captured at save or mid-session
  • Reinforcement-lite: counters and a distinct-date threshold
  • Gated graduation into AGENTS.md, with ungraduate to drain
  • Separate-budget load; truncation always stated
  • Compaction with a restorable cold archive
  • Zero-dependency test suite, CI on Ubuntu and macOS

out of scope Deliberately cut

  • No cron, background capture, or batch analyzer
  • No time decay; staleness is a lazy TTL check plus supersede
  • No confidence-score math
  • No committed or shared store yet
  • No cross-repo knowledge aggregation
  • No auto-graduation
The boundary invariant. Knowledge is just markdown, readable with no adapter; relay.sh owns every write, merge, and counter; the agent owns judgment and prose; adapters stay thin.
S-12

Hardened after a 3-agent design review

A Cognitive Forge review (challenger, explorer, decomposer) on 2026-06-22 found the draft's determinism broken at one seam, the id contract, with index consistency as the second risk and three holes in graduation. All six issues were folded in before the build.

#Issue the review surfacedFix as shipped
R-1Fact id contract undefined (--fact had no id, but merge keyed on id)Facts take an explicit --id; slugify rules and a 48-char limit are pinned
R-2Confirm-and-merge silently overwrote on an id collision--near before write; divergent body → .conflict sidecar + resolve, never overwrite
R-3A facts cap reintroduced silent partial continuityLoad states "N of M shown" whenever it truncates
R-4The knowledge index was a single point of failure that could driftLoad reads entry files directly; the index is a rebuilt cache only
R-5Graduation: uncapped surface, no retirement path, leaks local learning into a committed fileungraduate drains it; an 8-block nudge; the helper names the committed file on every graduation
R-6Bare seen ≥ 3 couldn't tell a coincidence from a patternGate is sessions ≥ 3, distinct dates, fed by helper-stamped provenance

enh Provenance

The helper stamps source: history/<date>.md#session-N at no agent cost, which feeds the sessions gate and knowledge why.

enh confirmed + TTL

A fact reinforcement counter and a freshness window checked lazily at load; staleness needs no scheduler.

enh Conflict markers

Git's "never auto-resolve, always surface" rule for facts: both sides kept, flagged at load, resolve picks one.
